# Olist E-commerce Analytics

Olist 巴西电商公开数据 SQL 分析作品集。重点：数据质量、明细预聚合、订单级宽表、月度/地区配送表现、延迟区间和结果校验。不重复收录已完成的 Tableau 可视化。

## 技术栈
MySQL、DataGrip、SQL；Tableau 图表在仓库外维护。

## 目录
- `docs/`：项目说明、数据模型、指标口径、业务分析、复现指南
- `sql/`：质量检查、订单宽表、整体/月度指标、配送分析、地区分析、延迟区间、结果校验
- `results/`：仅保存经复核的聚合结果

## 数据表
项目记录的 DataGrip 行数：orders 99,441；order_items 112,650；order_payments 103,886；order_reviews 99,224；customers 99,441。历史 CSV 行数和导入行数曾有差异，这些数值仅作历史记录，复现时请重新核对。

## 分析流程
1. 检查行数、关键字段空值、唯一性和关联完整性。
2. 商品、支付、评价等一对多明细先按订单聚合。
3. 创建 `order_analysis_wide`。
4. 分析整体/月度指标、配送表现、地区差异和延迟区间。
5. 创建月度汇总表并校验结果一致性。

## 口径提醒
商品金额与支付金额分别保存；未经明确口径不要直接把任一字段称作 GMV。准时率/延迟率分母建议为具备实际送达和预计送达时间的可评估订单。未送达订单不可自动视为准时。禁止未经聚合直接连接多张一对多明细表后求和。

## 复现
在 MySQL 导入 Olist 数据，核对字段后按 `sql/01` 至 `sql/07` 顺序执行。详情见 `docs/05_data_source_and_reproduction.md`。
